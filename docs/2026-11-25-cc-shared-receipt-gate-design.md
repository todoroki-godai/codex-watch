# Codex と CC の作業役で受領の確認を共有する

## Codex が使えない日も、CC の作業役を起こす前に止める

`codex-impl` の受領判定を `codex-watch` の `lib/` に切り出す。Codex の起動口と Claude Code（CC）の `Agent|Task` hook がその部品を呼ぶ。実装の完了条件は、Codex CLI も認証も使えない状態で CC の `impl-worker` にレビュー由来の直しを頼んだとき、受領3行のうち1行でも欠ける依頼と、本文のどこかに `Should` がある依頼がそれぞれ止まり、書式を満たす依頼が通ること。

今回の未対応は次のとおり。

- 2番目の作業で扱う実作業先の隔離。CC hook の `cwd` や依頼文に書かれたパスから、作業役が実際に書く場所を確認する処理は未対応。
- 3番目の作業で扱うレビューの発注と受け取りの照合。巡数、発注記録、返答全文と実効依頼文、対象 SHA と内容ハッシュの照合は未対応。
- 別課題の時間超過通知と、Codex の起動口にある課題番号・モデル選択などの他の判定の共有は未対応。
- 起動済みの作業役に `SendMessage` で直しを送る経路は `Agent|Task` の matcher の外にあり、未対応。

CC だけで作業する場合、CC が書いた成果物を tacchi が確認しても別系統のレビューは0本で、人間が全件承認する。別系統レビュー1巡、未解消の `[Must]` がある間の着手禁止、変異確認、人間の承認が必須の操作は現行どおり。この案の現行版に対する別系統レビューと着手判断は実装前に行う。 [工程別ルーティング](/Users/matsukaze-takashi/.claude/rules/pipeline-routing.md)・[レビューの関門](/Users/matsukaze-takashi/.claude/rules/review.md)

## CC では `impl-worker` の新規起動を対象にする

`tool_name` が `Agent` または `Task` で、`tool_input.subagent_type` が完全一致で `impl-worker` の呼び出しにかける。実装役の定義と、hook が `Claude で実装する理由:` を求める既存の識別を使う。対象の `tool_input.prompt` が欠落、空、文字列以外なら拒否する。`Claude で実装する理由:` は経路を選ぶ理由の欄で、`直しの出所:` と受領3行は元の `prompt` を受け取った共通部品が検査する。 [既存 hook の役割判定](/Users/matsukaze-takashi/.claude/hooks/guard-impl-worker-routing.py:84)・[実装役の定義](/Users/matsukaze-takashi/.claude/agents/impl-worker.md:2)

既定はこの作業役一つ。tacchi などのレビュー役は `Should` の基準や指摘原文を扱える。`general-purpose` や `mech-worker` は調査や機械作業にも使うため、そこへ書き込みを頼む経路は対象外とする。本文の `Should` や `作業の種類: 判断` で起動対象を推測する案では、レビューや調査が巻き込まれる。`直しの出所:` を対象判定に使う案では、その行を書き忘れた依頼を捕まえられない。名前と自己申告の検査であり、別の役を選ぶ場合や言い換えには効かない。Codex が使えない日の新規発注では `impl-worker` を選び、その事情を `Claude で実装する理由:` に書く。 [作業種別の既存判定](/Users/matsukaze-takashi/.claude/hooks/guard-impl-worker-routing.py:125)・[tacchi の基準追記](/Users/matsukaze-takashi/.claude/hooks/guard-impl-worker-routing.py:251)

## 共通部品は元の依頼文を1回読み、止める理由を返す

`lib/receipt_gate.py` に現行の判定と、拒否理由・控えを扱う小さな実行口を置く。判定に渡す入力は元の依頼文の UTF-8 バイト列。Codex は既存のファイルを指定する。CC hook は JSON のエスケープを解いた `prompt` を UTF-8 にして、整形せずに標準入力で渡す。部品の呼び出しにシェルは挟まない。コマンド引数にも本文は載せない。

| 入力 | 判定 |
| --- | --- |
| UTF-8 として読めない、または NUL を含む | 拒否する。 |
| `直しの出所:` | 字下げなし・半角コロン・空でない値が1行必要。値は `なし` または `レビュー` で始める。 |
| 出所が `なし…` | 出所行より後ろに `巡[0-9]` または `指摘を反映` があれば拒否する。 |
| 出所が `レビュー…` | 出所や受領の行も含む全文に `Should` があれば、大文字小文字を問わず拒否する。次に `受領①累計:`・`受領②件数:`・`受領③7段:` がそれぞれ字下げなし・半角コロン・空でない値で1行あることを確かめる。 |

現行の文字列判定をそのまま移す。受領欄の内容の真偽や人間の承認は既存手順で確認する。部品は成功時に無出力で終了コード `0`、拒否時は標準エラーに理由と直し方を出して `2` を返す。読取・記録エラーも理由を出して `2`。呼び出す側が観測した想定外の終了も起動不可とする。 [現行判定と拒否案内](../bin/codex-impl#L40)・[依頼文の契約](../README.md)

**控えは両入口で残す。** 既定は Codex と同じく、語で止めたときだけ写し1件と JSONL 1行を `~/.codex-watch/receipt-gate-stops/` と `~/.codex-watch/receipt-gate-stops.log` に記録する。受領欄の欠落など、語に当たらない拒否は理由を返す。すべての拒否を保存する案は、依頼文の保管範囲が広がるため採らない。写しは元のバイト列、権限 `0600`、既存ファイルの上書き不可。Codex の `time`・`prompt`・`match`・`snapshot`・`sha256` は現行どおり。CC の行は元ファイルがないので `prompt: null` とし、`entrypoint: cc` を足す。写しまたはログの保存に失敗したら両入口とも拒否する。ログへの追記だけ失敗した場合、先に保存できた写しは残す。 [現行の保存形式](../bin/codex-impl#L78)

## 両入口で判定を済ませてから注意文を足す

| 入口 | 呼び出しと停止 |
| --- | --- |
| `bin/codex-impl` | 起動スクリプト自身の隣の `../lib/receipt_gate.py` を `python3` で呼び、現行のインライン判定を置き換える。依頼ファイルを既存の時点で検査し、読取・記録・部品起動の失敗は起動前に止める。成功時は後続の既存処理に進み、手元の試験範囲の注記を先頭、`templates/hash-check.md` を末尾に足す。 |
| CC の `guard-impl-worker-routing.py` | `Path.home()` を基点に、既存の tacchi 用テンプレートと同じ `~/matsukaze-utils/codex-watch` の `lib/receipt_gate.py` を絶対パスで呼ぶ。対象判定後の必須処理を現行末尾の `except Exception: return 0` の外に置き、そこから `0` を返せるのは共通判定を通過し、既存の必須チェックと注意文の組み立ても成功した場合に限る。部品の不在・読取不能・例外・異常終了・応答の異常・タイムアウトは hook 自身が標準エラーに原因と復旧先を出し、`2` を返す。子プロセスは既定3秒で打ち切る。 |

CC は登録済みの `PreToolUse` を使う。元の `prompt` に判定を1回かけ、通過後に試験範囲の注記を先頭、同じ `templates/hash-check.md` を末尾に足し、他の入力欄を保った `updatedInput` を返す。試験範囲は Codex の既存の1文を使い、手元で全体試験を回せる明示依頼の例外も含める。テンプレートを読めない場合も対象の起動を止める。承認に関わる `permissionDecision: allow` は出さない。tacchi の既存の基準追記は従来の経路で行う。 [現行の注記](../bin/codex-impl#L325)・[CC の登録](/Users/matsukaze-takashi/.claude/settings.json:90)・[Claude Code の hook 仕様](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)

auto mode が `updatedInput` を受けて再発注を求めた場合、新たなツール呼び出しとして受信した本文を1回判定する。注記とテンプレートがすでに同じ先頭・末尾にあれば追記を省く。初回も再発注も、判定には受信本文をそのまま渡す。 [auto mode の再発注仕様](https://code.claude.com/docs/en/hooks#pretooluse-updatedinput-in-auto-mode)

## 巻き添えと故障時の停止を限定し、差分を戻せるようにする

1. **誤って止まるもの。** `impl-worker` に出す正当な新規依頼でも出所欄を忘れると止まる。レビュー由来の依頼に `Should 0件` や指摘の引用が残る場合、また新規依頼で出所行の後ろに `巡1` などがある場合も止まる。拒否理由と行の書き方を返す。既存 hook の登録範囲はそのまま使い、今回の判定で止める範囲は前述の作業役に限る。過去の依頼に対する件数は未測定。
2. **確認が壊れたとき。** 対象と識別できたら、本文の不備、部品側の故障、追記・出力中の例外まで起動を止める。判定部品は対象の分岐まで読み込まないので、部品が壊れていてもレビュー役などにはこの故障が波及しない。外側の JSON が壊れて対象を識別できない入力は既存の扱いを維持する。hook 自体が起動しない障害はこの分岐で制御できないため、初回の反映時に実際の起動を確かめる。 [現行の例外処理](/Users/matsukaze-takashi/.claude/hooks/guard-impl-worker-routing.py:277)・[Claude Code の終了コード仕様](https://code.claude.com/docs/en/hooks#exit-code-2)
3. **配布と戻す差分。** 先に `codex-watch` の部品と起動口を同じ版で反映し、次に CC 側の hook と受領ルールを反映する。前者だけ更新した間は Codex の判定のみ有効で、CC の起動口にはまだ効かない。CC 側だけ先に入れた場合や先に部品を取り除いた場合は、対象の CC 発注が部品不在で止まる。両方を戻すときは CC の接続・受領ルール・関連試験を先に戻し、次に Codex の抽出差分を戻して元のインライン判定を復元する。戻した状態では CC 側の受領確認が未対応に戻る。既存の停止記録には手を加えない。

部品の置き場は既存の絶対パス規約に合わせる。設定可能な探索先、作業ディレクトリからの探索、hook 側へのコピーも選択肢だが、既定は固定した正本1箇所。Codex CLI や認証への依存も増えない。先に入れた部品を後で更新するときは、既存 hook が使う標準入力と終了コードの契約を保つ。

## 両方の実入口で拒否と通過を観測し、変異で検査を確かめる

| 検査 | 実装時に確かめること |
| --- | --- |
| 共通部品 | 出所の欠落・重複・不正値、受領各行の欠落・空欄・重複、`なし…` の後ろにある既存の検査語、レビュー由来の全文にある `Should` の大小文字と位置を固定する。正当な新規依頼、3行付きの直し、CRLF で通過する。 |
| Codex の実入口 | `tests/test_codex_impl_receipt.py` の陰性・陽性対照・変異の全ケースを維持する。実物の `bin/codex-impl` を起動し、受領判定後の既存の目印で止めて CLI・認証に進ませない。依頼文・控え・記録の保存条件と、部品や Python の故障時に後続へ進まないことを検査する。インラインの既存変異は移動先に当てる。 |
| CC の実入口 | 既存 `test_guard_impl_worker_routing.py` から実物の hook に JSON を流す。実装理由・作業種別・終端チェックを満たした `Agent` と `Task` で、受領各行の欠落と `Should` が個別に `2`・`updatedInput` なしになることを確かめる。有効な直しと新規依頼は `0` で、受信した本文を保った入力に注記が1回だけ付く。同じ語を含む tacchi の正当なレビュー依頼は既存の点検を通る。部品不在・読取不能・例外・タイムアウト・保存失敗は拒否し、部品なしでも対象外には既存の処理が適用されることを確かめる。認識済みの `impl-worker` の本文不正は、新しい拒否として既存テストの期待値を更新する。 |
| 変異と対照 | 一時領域の実装コピーで、受領1行を免除する変異と `Should` を見逃す変異を当て、両入口の拒否試験がそれぞれ赤になり、正当な依頼は緑のままと確かめる。CC では共通判定の故障を成功扱いにする変異も当てる。変えた箇所の一意性と差分を確認し、変異箇所に置いた目印が実入口の実行で出たことを別の証跡で確かめる。変異を外して元の検査を再実行し、緑に戻す。 |

同じ依頼を両入口へ流すケースでは、理由と控えの件数を確かめる。原本と写しの一致は、同じ順で並べた SHA-256 と件数で比較し、不一致時だけ本文を開く。CC の試験は一時 HOME に `matsukaze-utils/codex-watch` を再現して実物の部品を置く。Codex CLI の入らない状態でも拒否と通過を検査でき、普段の hook やログを汚さない。既存の実依頼由来の Codex 試験素材を残し、CC 側も反映前に持ち出し可能な実依頼で dry-run する。反映後は実セッションで Codex CLI・認証なしの拒否2件と通過1件を確認する。実際の Agent 起動可否はこの段階で確定する。

手元は変更したファイルと近傍の試験、依存先込みの lint・型検査まで。パッケージ・リポジトリ全体の試験は、依頼で明示された場合を除き、頭が AWS で回す。今回は設計段階のため、上記の動作と変異は未実施。
