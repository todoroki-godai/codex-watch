# 見込み超過の知らせに原因の手がかりを添える（設計・#0）

## 目的
本人の依頼（2026-11-22・原文「見込みより伸びている場合って、大概何かにはまってたり、設計がわるかったりする。何が原因でのびているか？を調べるっている仕組みを入れたい」）。本人は調査結果を見て「DB待ちを課題にし、仕組みは最小」を選んだ。
OVERDUE（見込みの2倍を超えた知らせ）が鳴ったとき、頭が log を開く前に「何に詰まっていそうか」を1行で見られるようにする。

## 根拠（件数）
- 2026-11-22 の集計（harness-nudge 枝 `research/overrun-causes`・commit 8dc4245 の `docs/research/overrun-causes-20261122/`）で、全 run 6,691件のうち見込みあり 1,116件、2倍超え8件。8件とも主因は環境の詰まり（共有DB待ち6・dev DB 読み取り待ち1・DB検査の時間切れ1）で、同じ台本の機械判定が8件中8件で一致。全件が同じ原因だったため、他の原因を見分けられるかは未確定。

## やること（最小）
`bin/codex-watch` の OVERDUE の行の**末尾に**手がかりを添える（別の行にしない。stdout の1行が1通知なので、行を増やすと通知が1件増える）。
```
OVERDUE: <run> 見込みN分の2倍を超過（経過M分）。git log・status と出力を読んで判断する／手がかり（文言の一致数・原因の判定ではない）: 時間切れ・接続・ロック関連 N行・権限で断られた N行・同じエラー行の最多 N回
```
- 数え方は調査台本 `count.py` の `ENVIRONMENT`・`PERMISSION`・`ERROR` の正規表現と、同じエラーの同一視の処理（ANSI と行頭の時刻を除き、連続する空白を1つにまとめてから文字列で比べる。`count.py:167` 付近）をそのまま移す。
- 一致数は文言の一致であって原因の判定ではない。手順に引用した文言にも一致し、「検査枠待ちのため開始を見送る」のような独自の待機文言には一致しない。0件は「詰まっていない」の根拠にならない。この注意を README の OVERDUE の説明に1行で書く。
- 読む量と時間に上限を置く: log の末尾 8MB だけを読み、集計は 10 秒で打ち切る。上限到達・log が無い・読めない・集計器の異常終了のときは、手がかりの部分を「手がかり: 数えられず（<理由1語>）」に置き換え、OVERDUE の行は必ず1行出し、終了の仕方（`.overdue` の作成・終了コード 0）は今までどおりにする。
- 数えるのは python3 の標準ライブラリだけ。判定（続けるか止めるか）は今までどおり頭が行う。閾値・知らせの回数・終了コードは変えない。

## 足さないもの（7段）
- ㋑既存: OVERDUE の分岐と python3 の埋め込みが既にある。そこに数行を足す。新しいファイル・設定・常駐処理は作らない。
- 「設計の誤り」「範囲の膨張」の自動判定は足さない（今回の8件に例が無く、正規表現では見分けられない）。
- 原因の記録をファイルへ残す仕組みは足さない（必要になったら調査台本で後から数えられる）。

## 検証
- 既存の `tests/test_progress_overdue.py` の入口試験（`test_boundary`・`test_verdict_alive` 付近）を使い、OVERDUE が手がかり付きで1行だけ出ること、先に VERDICT が出る場合は `VERDICT` → `OVERDUE` の2行になることを固定する。
- 陽性: 環境・権限の文言と、空白だけ違う同じエラー行を含む log で、表示件数まで照合する。通常の log と、正規表現に一致しない待機文言だけの log で 0 になること。
- 失敗時: 集計器の異常終了・時間上限到達・log 無しで、OVERDUE が1行・`.overdue` あり・終了コード 0。
- 陰性: 手がかりを別行に出す／正規表現を空にする／空白の正規化を外す／集計の失敗で OVERDUE が出なくなる／時間上限を外す、の各変異で試験が赤になること。
- 発火時点の log で既知のDB待ちを拾えるかは、`~/.codex-watch/` の該当 run の log を OVERDUE の時刻までで切って1件照合する（読むだけ）。
- 全試験の結果行。

## 完了条件（本人から見て分かる完了）
見込みの2倍を超えた知らせに、何に詰まっていそうかの1行が付く。知らせが来なくなる・増えることはない。
