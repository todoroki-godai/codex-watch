## 毎回の走査と起動時の設定

### 走査は Codex 標準の一覧取得を使う

1. `-C` で実際に使う作業場所と起動時の設定を揃え、同じ CLI 0.169.1 の `app-server --stdio`（＝かんたんに言うと、Codex の内部機能を問い合わせる窓口）に標準入出力で接続する。`initialize`／`initialized` 後に `skills/list` を `cwds: [作業場所]`、`forceReload: true` で1回問い合わせる。会話の作成・モデルへの依頼は行わない。応答の `name`、`path`、`scope`、`enabled`、`pluginId` と `errors` を使う。これで新しく追加された skill も次回の走査に入り、許可リストに無ければ外れる。［[公式の App Server 説明](https://learn.chatgpt.com/docs/app-server)・[0.169.1 の一覧取得](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/app-server/src/request_processors/catalog_processor.rs#L546)・[応答形式](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/app-server-protocol/src/protocol/v2/plugin.rs#L471)］
2. 走査には個人共用の `$HOME/.agents/skills`、互換用の `$CODEX_HOME/skills`、内蔵の同 `.system`、管理者配布の skill、作業場所からプロジェクトルートまでの `.agents/skills` と信頼済みの `.codex/skills`、有効なプラグインの提供先が入る。プラグインは `plugins/cache` の全バージョンを一括検索せず、設定・提供元の定義から Codex が選んだ版を使う。`~/.claude/skills` には `~/.agents/skills` などのリンクから到達する。すべてのローカルパスは本番側のリンクをたどり、実在する通常の `SKILL.md` の絶対パス（＝かんたんに言うと、別名を除いたファイルの住所）で比較する。壊れたリンクで Codex 自身が掲載しない項目は対象外。掲載済みで実体を確認できない項目は異常として停止する。［[0.169.1 の探索先](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/ext/skills/src/host_roots.rs#L90)・[公式の配置説明](https://learn.chatgpt.com/docs/build-skills#choose-where-to-put-skills)］
3. 走査専用プロセスは、起動時に内蔵 skill の配置やプラグインの自動同期を始め得る。本人の設定を守るため、`CODEX_HOME`（＝かんたんに言うと、Codex が設定や記録を探す場所）の隔離した写しで実行する。設定・選択された版と提供元を解決するのに必要なローカルファイルだけを用意し、個人・プロジェクトの配置先は読み取り専用で見せる。この端末では標準の `/usr/bin/sandbox-exec` を候補とし、走査子プロセスに OS 側の制限を掛けて書き込み先を一時領域だけにして外部通信を遮断する。資格情報・会話記録・記憶のファイルや資格情報の環境変数は持ち込まない。照会には標準入出力を使い、常駐サーバーへ接続しない。`CODEX_HOME` 内のコピーに対して返ったパスは対応する元の版のパスへ戻してから実体を解決する。走査用プロセスで実際にこの制限を掛けられない場合や、同じ設定・版・探索先を再現できない場合は停止する。実作業側の権限設定は既存のものを使う。［[0.169.1 の起動時同期](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/core-plugins/src/manager.rs#L2993)・[内蔵 skill の配置処理](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/ext/skills/src/host_service.rs#L502)］
4. 実装時に、走査結果が実起動で選べる skill と一致することを確認する。クラウドや実行環境側で初めて追加される skill までこのローカル一覧で列挙できるとは限らない。そうした出所や、認証なしの一覧取得で選択結果が変わる構成は、照合が取れるまでは絞り込みの適用対象にしない。走査と起動を連続させ、走査中に設定や有効な版の変更が分かったら停止する。起動後の変更を凍結する仕組みは持たず、これは利用する手順を絞る設定であり、実行権限は既存の設定が管理する。

### 実作業は現在の設定に `-c` で追記する

- 0.169.1 では `-c`（＝かんたんに言うと、その起動だけに設定を重ねる引数）を TOML として解釈し、ドットで区切った設定先へ入れる。配列内に表を置く形と真偽値の両方を渡せる。後述の二つの値はそれぞれ1引数。公式説明と、タグが指すコミット `c376cf7396eff83ce4c6ac61b9553df142e7a0be` のソースで確認した。［[公式の起動時上書き](https://learn.chatgpt.com/docs/config-file/config-advanced#one-off-overrides-from-the-cli)・[値の解釈](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/utils/cli/src/config_override.rs#L49)・[起動時設定への取り込み](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/config/src/loader/mod.rs#L445)］
- skill は `-c 'skills.config=[{path="/absolute/path/SKILL.md", enabled=false}]'` の形で、現在有効かつ許可リスト外の実体パスをすべて1つの配列に入れる。0.169.1 の skill 専用処理は、ユーザー設定と起動時設定のルールを順に読み、同じ skill に当たる後の指定を優先する。追加は `enabled=false` のみで、許可内の既存無効化も引き継ぐ。プラグイン本体の有効設定には触れず、同梱の連携やフックを保つ。［[skill ルールの重ね方とパスの正規化](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/config/src/skills_config.rs#L99)・[プラグイン個別 skill への適用](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/core-plugins/src/loader.rs#L948)］
- 記憶は `-c memories.use_memories=false` を渡す。0.169.1 の読み込み側の条件と、先行実験の差し込み1→0がこの選択の根拠。［[公式の記憶設定](https://learn.chatgpt.com/docs/customization/memories#configure-local-memories)・[0.169.1 の差し込み条件](https://github.com/openai/codex/blob/c376cf7396eff83ce4c6ac61b9553df142e7a0be/codex-rs/ext/memories/src/extension.rs#L43)］
- `bin/_codex_common.sh` の共通処理から、両起動口の既存の実行引数に追加する。`python3` で文字列を TOML として組み立て、`tomllib` で読み直して期待したパスと型・値に一致することを確認する。引数配列として渡し、名前やパスをシェルで再解釈させない。走査・検証は実行の予約やバックグラウンド起動の前に完了させ、既存の作業権限、GitHub/AWS の名義、モデル設定を引き継ぐ。

### 一時ホームで実作業する案

実作業には一時ホームを採用しない。先行試験では機能したが、キャッシュだけでもこの端末で `du -sh` 464M（2026-11-18）あり、写しの作成時間・書き込み量は未計測。APFS のコピー時共有（＝かんたんに言うと、最初は同じディスク領域を共有し、書くときに分ける機能）でも、ファイル数に応じた処理や後始末、版の照合は要る。走査専用の写しの所要時間・容量も実装時に測り、毎回の起動に加わる負担を記録する。

将来の版で `-c` が効かなくなった場合は、その版で絞り込みを停止して設計を再確認する。実作業まで写しで行う案には、通常の認証が新しいホームで成立するか、セッションが別の場所に保存されても見張りが追えるかの検証が追加で要る。試験で使った `auth.json` の複製を運用の前提にせず、まず環境側が提供する既存の認証手段で成立するかを確かめる。認証の複製が必要な方式へは自動で切り替えない。一時領域は所有者限定で作り、正常終了・異常終了とも終了したプロセスを確認してからその実行の領域だけを片付ける。

走査が時間内に終わらない、応答が欠ける、提供元やパスが解決できない、設定の組み立てに失敗する場合は、**黙って通常起動せず停止する**。CLI 起動後に設定エラーを返された場合も通常設定に切り替えて再起動する処理は行わない。通常起動すると、発注者が切ったつもりの記憶や不要な手順が届き、負荷も戻るため。終了コードと原因を返し、必要なら発注者が該当項目を修正するか、意図して `off` で起動し直せるようにする。設定本文や資格情報は失敗ログに出さない。日常ログに残すのはモード、走査件数、残す件数、外す件数、走査時間と短いエラー理由。

## 実装後の検査

1. **単体試験**で一覧応答を差し替え、有効な版の選択、新規 skill、作業先の配下と祖先、同名の旧版・別実体、リンクと版変更、内蔵・管理者配布、既存の無効化を再現する。引数は TOML として再読込し、許可外だけが `false` になること、空配列・日本語や空白の入ったパス・モードごとの記憶設定を確認する。応答欠損、走査期限切れ、曖昧名、引数の上限超過では両起動口とも実行されないことを、テスト用の起動コマンドで確認する。全体 off は走査なしで既存引数のまま実行、記憶だけ keep は skill の上書きだけと照合する。
2. **陰性試験**（＝かんたんに言うと、わざと壊して検査が失敗するかを確かめる試験）を独立に2本行う。許可リスト判定を無視して全件を通す変更では、既知の許可外1件が実行引数から漏れて失敗すること。既定時の記憶上書きだけを落とす変更では、起動引数の `memories.use_memories=false` が欠けて失敗すること。起動口が受け取った引数を検査し、ログ表示だけで合格を決めない。
3. **陽性対照**（＝かんたんに言うと、残すべきものが使えることの確認）では、通常版 `agent-browser` や `commit`、発注時の追加1件が有効のまま残り、同名の別パスと無関係な新規項目が無効になることを確認する。既存設定が無効にした skill は引き続き無効。走査用の隔離先を後始末した前後で、本物の設定、元の skill とリンクが更新されていないことも確認する。
4. **実機での最終確認**は実装担当とは別に取りまとめ側が実行する。まず両起動口をテスト用コマンドで通した後、本人の通常構成に相当する 検証用の作業場所で同じ短い依頼を外から1〜2回流す。優先は同じ起動口で既定と明示 off の2回。1回なら既定で、前回の数値は参考値とする。実行IDと会話記録を突き合わせ、初回 `host_skills.instructions` の件数とパス集合、`memories.instructions` の有無、最初の `input_tokens` とキャッシュ分、走査時間を記録する。合格条件は、予定した有効 skill が残り、許可外が0件で、既定の記憶差し込みが0件、同条件の off を取った場合に初回入力が減少すること。入力25,703や一覧29件を固定の合格値にはしない。

## 7段で止めた場所

1 そもそも要るか → 2 既にあるか → 3 標準ライブラリ → 4 プラットフォームの標準機能 → 5 導入済みの依存 → 6 1行で書けるか → 7 最小のコード。各行は左から調べ、採用できた段で止める。

| 足す仕組み | 止めた段 | 理由 |
| --- | --- | --- |
| 初期11件と発注時の追加・入切り | **7 最小のコード** | 依頼ごとに追加・復帰する口が要る。既存の起動口にこの指定はなく、標準のファイル・環境変数で入出力できても、名前の曖昧さや矛盾を1行で検証できない。1ファイルと両起動口の共通処理に収める |
| 対象の探索 | **4 プラットフォームの標準機能** | 必要な一覧は Codex が解決できる。汎用ファイル走査だけでは設定・探索順・プラグインから有効な集合を復元できない。`skills/list` を再利用し、独自の探索規則を持たない |
| 走査プロセスの隔離 | **4 プラットフォームの標準機能** | 通常の起動では同期が動くため、使い捨てのホームと OS の書き込み・通信制限を使う。標準ライブラリは一時領域を作れるが、別プロセスの書き込み制限まで担えない |
| パス解決・設定文字列の検証 | **3 標準ライブラリ** | 既存の Python 3.11 で `pathlib` と `tomllib` を使える。信頼の境目にあるパス・型・値・引数境界は検査を残す |
| skill と記憶をその回だけ切る | **4 プラットフォームの標準機能** | 既存の起動口にある `-c` の渡し方を使い、Codex が解釈する配列と真偽値を追加する |
| 失敗時の停止と片付け | **7 最小のコード** | 終了コード・期限・一時領域の片付けには既存の処理と標準ライブラリを使う。不完全な応答や設定を成功扱いしない分岐と、実行ごとの領域だけを片付ける安全策は残す |
| 検査 | **2 既にあるか／7 最小のコード** | 起動口を偽コマンドで検査する既存テスト、会話記録を数える既存の計測方法を再利用する。明示依頼の陰性2本と陽性対照はその仕組みに追加する |
| 本人用・実作業用の別ホームを常設する機構 | **1 そもそも要るか** | 実作業の上書きは起動引数で足りるため、資格情報や状態の複製と同期の仕組みは設けない |
