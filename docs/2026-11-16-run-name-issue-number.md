## 判定の規則

- 番号の取り出しは、いまの必須検査と**同じ規則**にする（`value` 全体から `#[0-9]+` を探し、
  先頭60字以内で終わるものの最初の1件）
- **取り出せないときは `0`**（検査が異常で通る経路が実在する。`CODEX_SUMMARY` に不正な
  UTF-8 を渡すと検査は 0 を返し、取り出しは 2 を返す＝巡1の [Must] M1 の実測）
- label に番号があるかは、`(^|[^0-9])N([^0-9]|$)` で見る（`#1987` の label で `198` に
  誤一致しない。`1987` と `11987` を同じと見ない）
- **足す部分は数字と `-` だけ**。label 側の文字は変えない（**巡1の [Must] M2 で直した**。
  前の版は「出す名前は `[A-Za-z0-9._-]` だけにする」と書いていて、label を変えないことと
  食い違っていた。日本語の label は実際に使われており〔`~/.codex-watch` の run 名 5,565件中
  32件・2026-11-16 取得。内訳は「シ」等の日本語で、`/` は0件〕、この文字集合にすると
  いまの呼び出しを拒否してしまう）

1. 付ける処理を消す → 番号の無い label が素通りする
2. 既に番号がある label にも足す → `1987-1987-…` になる

   番号の無い名前になる。既存の「異常時は起動を続ける」要求（`tests/test_codex_summary.py:209`）は
   緑のままであること
7. **切り詰めた文字列の側を探す実装に替える**（巡1の [Should] S3）→ 60字の位置で数字列が
   途切れる入力で、番号が変わる／取れなくなる
8. **複数の番号があるとき2件目を採る**（巡1の [Should] S3）→ 先頭の番号を使わなくなる
9. **走行中の run の維持**（巡1の [Should] S3）: 新しい起動の前後で、走っている run の
