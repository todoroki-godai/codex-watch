# Codex の版が変わったら自動で確かめて絞り込む／起動ごとのトークンの内訳を集計する（設計）

出所: 本人 2026-11-23（harness-nudge の窓への直接入力）「codexアップデートしたら、自動で適用したい。codexトークンの効率化はかりたい」。問いへの回答は「版が変わったら自動で確かめてから効かせる (Recommended)」「run ごとに記録して週ごとに集計 (Recommended)」、範囲を内訳（やり取りの回数・ファイル読み・試験の出力）まで広げる案に「推奨で」。
前提の変更: PR #82（e257239）で確認済みの版を手で 0.171.0 にした。本設計は次の版から手作業を無くす。

## いまの動きと困りごと
- `lib/codex_launch_skills.py` は `codex --version` が `CLI_VERSION` と一致しないと絞り込みを省く（`main` の `version_supported`）。11/22 06:24〜11/23 の間、版を読めた552起動すべてで省かれ、気づいたのは偶然だった（測定: 枝 research/cli-0171-narrowing 17162bf）。
- 1本あたりの入力は sol 約747万トークン（11/22 実測）だが、どこで使ったかの内訳を見る手段が無い。起動直後の読み込みは約4万で、その外が大半と見ているが未実測。

## 求め
1. 確かめていない版で起動したとき、1つの版につき1回だけ、起動口が小さな確認の起動（以下「試し起動」）を自動で行い、絞り込みが効くと確かめられたら、その版でも絞り込む。
2. 確かめられなかった版は今までどおり絞り込みを省いて起動する。その版について1回だけ知らせる。
3. 起動ごとのトークンと内訳を、集計コマンド1本で週・モデル・起動口・版ごとに見られる。

## 守る性質（変えないもの）
- 試し起動の失敗・時間切れ・判定不能で、本来の起動を止めない（今の「省いて起動」へ戻るだけ）。止まる範囲は増やさない。
- 確かめ済みの版（`CLI_VERSION`）の動き、明示の `CODEX_SKILLS_FILTER=off`、レビューの追加指定の検査は今のまま。off のときは補助の処理が失敗しても起動を止めず、`cli_version=不明`・`launch_skills_filter=off` を書いて続ける。
- 既存の試験・変異確認・OVERDUE の知らせ・モデル指定の必須化は削らない。

## 1. 版の自動確認
- 起動口は PATH の全候補と `NVM_DIR`（未指定なら `~/.nvm`）の Node ごとの候補を実体で重複除去し、読めた版を数値で比較して最新を選ぶ。同版は PATH の先着を優先する。`CODEX_WATCH_CODEX` の絶対パス指定時はその実行ファイルだけを使う。版確認・試し起動・本起動には同じパスを渡し、状態ファイルの `codex_path` に記録する。
- 証明するもの: 「その版の CLI が、起動口の絞り込みの上書き（`-c skills.config=[…enabled=false]`）を受け取り、外した実体を一覧から消す」こと。**記憶は自動確認の対象にしない**（設計巡3の本人承認「残れば記憶の判定を外して skill だけに縮める」による縮小）。自動確認で合格した版では記憶の上書き引数（`-c memories.use_memories=false`）を付けず、Codex の既定どおり記憶を読む。記憶の上書きは、手で確かめた `CLI_VERSION` の版でだけ付ける（今の動き）。これは CLI の版で決まる性質として扱い、合格を同じ版の別の作業場所・`CODEX_HOME` にも使う（どの skill を外すかは起動ごとに列挙し直すので、作業場所の違いは列挙側が担う）。
- 置き場: `~/.codex-watch/cli-versions/<版>.json`（1版1ファイル。`status`、`probe_run`、`transient`、判定不能の `last_reason`、判定不能が続いた失敗の `failed_at`）。書き込みは同じディレクトリの一時ファイルから `os.replace`。確かめ済みの集合＝`CLI_VERSION` ∪ `status=verified`。
- 状態の移り方（1版につき確定の判定は1回）:
  - 一致 → verified。
  - 明確な不一致（一覧は取れたが、残した組と違う）→ その1回で failed。そのときだけ標準エラーに1行知らせる。以後その版は知らせずに省いて起動し、状態ファイルに `launch_skills_filter=skipped:autoverify_failed` と書く。
  - 一時的な失敗（時間切れ・記録が見つからない・一覧の節が無い・外す実体が0件で証明にならない・試し起動の準備で例外）→ 理由を `last_reason` に保存し、`transient` を1増やす。3回に達したら failed と時刻を保存して知らせ、24時間後に1回再確認する。再び判定不能なら時刻を更新し、次の24時間は再確認しない。旧形式で時刻がない判定不能の failed は直ちに再確認する。明確な不一致は恒久の failed とする。
  - 試し起動中の system skills の入れ直しは、対象と親がシンボリックリンクでない実ディレクトリである場合に限り許容する。親の同一性と他の子の一覧・実体は引き続き確認し、設定ファイルなど他の監視対象も検査する。
- 流れ（`main` の版判定の直前に足す。確かめ済みの版・`CODEX_SKILLS_FILTER=off`・`CODEX_SKILLS_AUTOVERIFY=off` は今までどおりで試し起動しない）:
  1. 版のファイルが verified なら絞り込む。failed なら省く。
  2. それ以外は `<版>.lock` を `fcntl.flock(LOCK_EX|LOCK_NB)` で取る。取れなければ待たずに今回は省いて起動する。
  3. 取れたら**ロックの中でファイルを読み直し**、まだ判定が要るときだけ試し起動し、結果の書き込みまでロックを持つ。
- 試し起動の守り: 試し起動に関わる処理（引数の生成・ロック・状態の読み書き・子プロセス・記録の照合）の例外は、すべて捕まえて今の「未確認の版」の経路（省いて起動）へ戻す。試し起動の終了コードは判定に使わず、会話記録の一覧だけで判定する（起動時の hook が失敗して非0で終わっても、記録が一致すれば verified）。列挙の15秒の期限（`SIGALRM`）は試し起動に入る前に解除する。レビューの追加指定の検査（`check_review`）は今のまま止める（既存の動き）。
- 試し起動の形: 版の確認に使ったのと同じ実行ファイルのパスで `codex exec` を起こす（`--version` と試し起動で別の実行ファイルに解決させない）。本来の起動と同じ作業場所・`CODEX_HOME`・絞り込みの引数。記憶の上書き引数は付けない。サンドボックス `read-only`・モデル `gpt-6.1-terra`・effort low・時間切れ120秒（時間切れはプロセスグループごと止める）。依頼は「何も読まず何もせず OK と返す」を標準入力で渡し、本来の起動のレポートファイル・標準入力は共有しない。起動時の hook が失敗しても会話記録が取れれば判定する。`read-only`・low で 0.171.0 の実物が判定できることは、実装の最後に実起動1回で確かめる（費用は 0.171.0・`workspace-write`・medium の同型で入力24,329／うちキャッシュ7,040・出力57、run 0-probe0171-20261123-114521-98287）。
- 判定: ログの `session id:` から `$CODEX_HOME/sessions/**/rollout-*<id>.jsonl[.zst]` を引く。その会話の**最初の** `<skills_instructions>` を含む developer メッセージの `### Available skills` 節から（掲載名, 正規化した実体パス）の組を取り出し、絞り込みで残した組の集合と比べる（同名で別の実体も区別する。節が無い＝一時的な失敗、節はあるが空＝明確な不一致）。
- 状態ファイルには、すべての経路で `cli_version=<版>` と `launch_skills_filter=` の値（`on`・`on:autoverified`・`off`・`skipped:unverified_version`・`skipped:autoverify_failed`・`skipped:autoverify_transient`）を書く。

## 2. トークンの内訳の集計
- 新しい記録もキャッシュも作らない。集計のたびに、対象期間の状態ファイル（起動口・絞り込みの状態）・ログ（先頭のヘッダーのモデルと版・`session id:`）・会話記録（`token_count`・ツールの呼び出しと出力）から求める。過去の run で版や絞り込みの欄が無いものは「不明」とし、既定の成功に寄せない。`.zst` は `zstd` があれば読み、無ければ「記録なし」に数える。
- 1本ごとに求める値: モデルへの要求回数・起動直後の入力（キャッシュ込み／抜き）・入力合計（込み／抜き）・出力合計（以上トークン）と、ツール出力の**バイト数**を種類別（読み＝`cat`/`sed`/`head`/`tail`/`rg`/`grep`/`ls`/`find`/`git show`/`git diff`、試験＝`pytest`/`npm test`/`pnpm test`/`vitest`/`jest`、その他）。呼び出しと出力は `call_id` で対応させ、`function_call`／`custom_tool_call` の両方を数える。種類はコマンドの名前で分けるので「推定」と表示する。バイト数はトークンの内訳ではない（同じ出力が後の要求で読み直される）ので、トークンとは別の列にする。
- 集計コマンド `bin/codex-tokens [--days N]`（既定7日・起動時刻が今から N 日以内の run）: 週（JST の月曜始まり）×モデル×起動口×版×絞り込みの状態ごとに、件数・中央値・合計を表で出す。走行中・状態欄なしの件数と、記録なしを理由ごと（ヘッダーが読めない／会話記録が無い／`token_count` が無い）に別の行で出す。ログの見出しは、先頭に続く Codex 自身のログ行（`<ISO時刻>Z ERROR|WARN|INFO `）だけを読み飛ばして探す（`bin/_codex_common.sh` の `extract_codex_log_header` も同じ規則）。

- 7 最小のコード: 試し起動と判定の関数、集計コマンド1本。

## 試験
- 陰性: ①一覧の組が違う（同名で外すべき実体が残る `agent-browser`／`agent-browser.backup` を含む）→ 恒久の failed ②試し起動中の設定変更 → transient ③節が無い・記録なし・時間切れ・外す実体0件 → 理由を保存し、3回で failed、24時間後に1回再確認 ④試し起動の準備で `SIGALRM`・`FilterError` → 理由を保存して transient ⑤ロックが取れない → 試し起動なし ⑥ロック取得前に他の起動が failed にした → 読み直して試し起動しない。system skills の実ディレクトリを入れ直しても、一覧が一致すれば verified とする。
- 陽性: 組が一致すれば verified、次の起動は試し起動せずに絞り込む。`CLI_VERSION` の版・`CODEX_SKILLS_FILTER=off`・`CODEX_SKILLS_AUTOVERIFY=off` は試し起動しない。自動確認で合格した版の本来の起動には skill の上書きが付き、記憶の上書きは付かない。
- 変異: 判定を名前だけの比較に戻す／ロックの中の読み直しを外す／試し起動の例外を外へ漏らす／自動確認で合格した版に記憶の上書きを付ける、の各々で赤を確かめる。変異の分岐が試験で読まれたことを機械で確かめる。
- 集計: 実物の会話記録から作った小さな試験用の記録で、要求回数・入力・`call_id` で対応させた種類別バイト数が手で数えた値と一致する。版や絞り込みの欄が無い run は「不明」に入る。

## 予測（simplest-first の運用に合わせて書く）
- 次に Codex の版が上がった日、手で版を書き換えずに、その日の起動の9割以上が `launch_skills_filter=on` か `on:autoverified` になる。確かめる日: 次の版上げの翌日。
- 集計を始めて7日後に、ツール出力のバイト数のうち「試験」と「読み」のどちらが大きいかが分かり、大きい方を次の節約の対象にする。
