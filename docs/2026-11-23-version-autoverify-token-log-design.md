# Codex の版が変わったら自動で確かめて絞り込む／起動ごとのトークンの内訳を集計する（設計）

出所: 本人 2026-11-23（harness-nudge の窓への直接入力）「codexアップデートしたら、自動で適用したい。codexトークンの効率化はかりたい」。問いへの回答は「版が変わったら自動で確かめてから効かせる (Recommended)」「run ごとに記録して週ごとに集計 (Recommended)」、範囲を内訳（やり取りの回数・ファイル読み・試験の出力）まで広げる案に「推奨で」。
前提の変更: PR #82（e257239）で確認済みの版を手で 0.171.0 にした。本設計は次の版から手作業を無くす。

## いまの動きと困りごと
- `lib/codex_launch_skills.py` は `codex --version` が `CLI_VERSION` と一致しないと絞り込みを省く（`main` の `version_supported`）。11/22 06:24〜11/23 の間、版を読めた552起動すべてで省かれ、気づいたのは偶然だった（測定: 枝 research/cli-0171-narrowing 17162bf）。
- 1本あたりの入力は sol 約747万トークン（11/22 実測）だが、どこで使ったかの内訳を見る手段が無い。起動直後の読み込みは約4万で、その外が大半と見ているが未実測。

## 求め
1. 確かめていない版で起動したとき、1つの版につき1回だけ、起動口が小さな確認の起動（以下「試し起動」）を自動で行い、絞り込みが効くと確かめられたら、その版でも絞り込む。
2. 確かめられなかった版は今までどおり絞り込みを省いて起動する。その版について1回だけ知らせる。
3. 起動ごとのトークンと内訳を、集計コマンド1本で週・モデル・起動口・版ごとに見られる。

## 守る性質（変えないもの）
- 試し起動の失敗・時間切れ・判定不能で、本来の起動を止めない（今の「省いて起動」へ戻るだけ）。止まる範囲は増やさない。
- 確かめ済みの版（`CLI_VERSION`）の動き、明示の `CODEX_SKILLS_FILTER=off`、レビューの追加指定の検査は今のまま。
- 既存の試験・変異確認・OVERDUE の知らせ・モデル指定の必須化は削らない。

## 1. 版の自動確認
- 置き場: `~/.codex-watch/cli-versions/<版>.json`（1版1ファイル。中身は `{"status": "verified"|"failed", "checked_at", "probe_run", "kept", "seen", "attempts"}`）。確かめ済みの集合＝`CLI_VERSION` ∪ `status=verified` のファイル。
- 流れ（`main` の版判定の直前に足す）:
  1. 版が集合にあれば今までどおり絞り込む。
  2. `status=failed` なら絞り込みを省く（知らせは出さない。初回の失敗時だけ出す）。
  3. ファイルが無い（または `attempts` が上限3未満）なら、同じ版の試し起動が重ならないよう `~/.codex-watch/cli-versions/<版>.lock` を `fcntl.flock` で取り、取れた1本だけが試し起動する。取れなかった起動は待たずに今回は省いて起動する。
- 試し起動: 本来と同じ作業場所・同じ絞り込みの引数で `codex exec` を `-s read-only`・モデル `gpt-6.1-terra`・effort low・時間切れ120秒で起こし、依頼は「何も読まず何もせず OK と返す」。費用は1版につき約1.7万トークン（11/23 の同型の起動の実測 17,346）、待ちは1回だけ1分前後。
- 判定: 試し起動の会話記録（ログの `session id:` から `~/.codex/sessions/**/rollout-*<id>.jsonl[.zst]` を引く）の developer メッセージ内 `### Available skills` の一覧に出た skill の名前の集合が、絞り込みで残した名前の集合と一致すれば verified。記憶は、確かめ済みの版の記録で記憶が差し込まれたときの印を実装時に特定し、その印が無いことも条件にする（特定できなければ skill だけで判定し、その旨を記録に書く）。一致しない・記録が見つからない・時間切れは attempts を1増やし、3回で failed にして1回だけ知らせる。
- 止め方: `CODEX_SKILLS_AUTOVERIFY=off` で試し起動をせず今の動きに戻す。戻す差分はこの変更の revert。
- 状態ファイルに `cli_version=<版>` と `launch_skills_filter=on:autoverified` を足す（集計で版ごとに分けるため）。

## 2. トークンの内訳の集計
- 新しい記録は作らない。既にある状態ファイル（モデル・起動口・版・絞り込みの状態）・ログ（`session id:`）・Codex の会話記録（`token_count`・ツールの呼び出しと出力）から、集計の時に求める。求めた結果は `~/.codex-watch/tokens-cache.jsonl` に run ごとに1行で控え、会話記録の sha256 が変わらなければ読み直さない。
- 1本ごとに求める値: モデルへの要求回数・起動直後の入力（キャッシュ込み／抜き）・入力合計（込み／抜き）・出力合計・ツール出力のバイト数を種類別（読み＝`cat`/`sed`/`head`/`tail`/`rg`/`grep`/`ls`/`find`/`git show`/`git diff`、試験＝`pytest`/`npm test`/`pnpm test`/`vitest`/`jest`、その他）。種類はコマンドの名前で分けるので「推定」と表示する（判断の材料で、検査ではない）。
- 集計コマンド `bin/codex-tokens [--days N]`（既定7日）: 週×モデル×起動口×版×絞り込みの状態ごとに、件数・中央値・合計を表で出す。会話記録が見つからない run は件数だけ数えて「記録なし」と出す。

## 7段
- 1 そもそも要るか: 要る（求め1は11/22 から全起動で省かれた実害、求め3は本人の要求）。
- 2 既にあるか: 版判定・絞り込み・状態ファイル・ログ・会話記録は既にある。集計の入力は全部既存のもの。測定の台本 `scripts/research/cli_0171_tokens.py`（枝 research/cli-0171-narrowing）の読み方を流用する。
- 3 標準ライブラリ: `fcntl`・`json`・`subprocess`・`statistics`。`.zst` は手元の `zstd -dc` を呼ぶ（測定の台本と同じ）。
- 7 最小のコード: 試し起動と判定の関数、集計コマンド1本。

## 試験
- 陰性: ①一覧が残した集合と違う ②記録が見つからない ③時間切れ ④ロックが取れない、のそれぞれで本来の起動が絞り込みなしで進み、①〜③は attempts が増え3回で failed と1回だけの知らせになる。
- 陽性: 一致すれば verified が書かれ、同じ版の次の起動は試し起動をせずに絞り込む。`CLI_VERSION` の版は試し起動をしない。`CODEX_SKILLS_AUTOVERIFY=off` は試し起動をしない。
- 変異: 判定を常に一致にする／ロックを外す／failed を verified と読む、で赤を確かめ、種類の違う変異を2件以上足す。変異の分岐が試験で読まれたことを機械で確かめる。
- 集計: 会話記録の写し（実物から作った小さな試験用の記録）で要求回数・入力・種類別バイト数が手で数えた値と一致する。
