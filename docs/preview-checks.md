# 発注前の点検節（有効化前に本人へ提示）

出所: 2026-11-10 本人の「推奨でお願い」「仕組み作りだけ今進めて」（main-index 中継、16:52 JST 受領）。レビュー起点ではない。起点は origin/main `32d2cccdede5a7c6c4523b16e2698711651db096`。

`bin/codex-review` は原本の依頼文を、前置きの付与・Codex 起動・巡の記録より前に検査する。判定は `lib/round_gate.py` の `missing_preview_checks()` 一つ。同じ対象・同じ `CODEX_REVIEW_KIND_LABEL` の巡数を既存の `ledger_own_round()` で一度だけ計算し、点検と前置きで共有する。同じ HEAD は同じ巡、設計後の最初のコード巡はコードの1巡目。総上限の数え方は変更しない。`CODEX_REVIEW_GATE_CHECK` は従来どおり巡数ゲートだけの dry-run で、実発注を行わない。

節の形（発注口で共通に使う書式）:

```text
点検:
- 突き合わせ: 既存コード・設定・関連課題を見た結果
- 出所の付記: 根拠の無い数値や「原文どおり」に出所を付けた／消した結果
- 直し残しの検索: git grep で古い言い方を探した結果
```

`点検:` の代わりに行頭の `## 点検` でもよい。項目は半角コロンの後に空白以外を1字以上書く。最初の2項目は1巡目から、検索は同じ種別の2巡目以降に必須。別の Markdown 見出しで節が終わる。項目は節より後に置き、別々の点検節の断片は合算しない。複数の点検節は1つが完全なら通る。字下げした節名・全角コロン・別の項目名は受け付けない。

検査は節と項目の有無だけ。自己申告であり迂回可能。内容の真偽、実際に git grep を行ったか、引用・コードブロック内かは判断しない。`codex-impl` の「直しの出所:」検査を前例として確認したが、今回変更する発注口は `codex-review` のみ。

不足時は exit 2 で発注を止める。文面は「依頼文に『点検:』の節が無い／項目が足りない（足りない項目: …）。書き手が出す前に点検して、結果を節に書く。決まりは review-gate スキルの『出す前の点検』」。停止した依頼は state も本文の巡行も増やさず、巡に数えない。

## 有効化前に見せる3点

1. **誤検知で止まるもの**。実際には確認済みでも、(a) 見出しを「確認:」とした設計レビュー、(b) 全角の「点検：」や字下げした節を使うコードレビュー、(c) 結果を別の Markdown 節に置いた再レビュー、(d) 検索済みだが2巡目の「直し残しの検索:」を省いた依頼は止まる。未対応の既存テンプレートからの発注も停止する。本人はこの書式制約を見てから有効化を判断する。
2. **失敗時は止める推奨**。不足・UTF-8読取失敗・台帳から巡を決められない場合は exit 2（fail-closed）。不明なとき通すと、書き忘れを受付で止める目的を失う。読取等の失敗は不足とは区別して stderr に理由を出す。巡数ゲートの既存の拒否・例外条件は維持する。
3. **戻す差分**。今回追加した受付ブロックと関数・試験・説明・証跡がロールバック単位。コミットは禁止されているため現時点で revert 対象の SHA は存在しない。CC がこのステージ済み差分を単独コミットした後、そのコミットを `git revert <今回の点検ゲートを収めたcommit SHA>` する。起点の `32d2ccc` は revert しない。CC はコミット後に対象 SHA をこの節へ追記する。
