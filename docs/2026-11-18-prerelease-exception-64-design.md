# 公開前特例の起動時診断と課題番号なし発注の再開手順

調査基点は `origin/main` の `7f061a9d18f76e7069c178f5d7f87a81ec6812b2`。観測・取得日は 2026-11-18 JST。実装の着手時期は未定。 [codex-watch #64（書式・前身継承・課題番号なしの3経路）](https://github.com/todoroki-godai/codex-watch/issues/64)

## 結論

- 通常発注の履歴出力は発注IDを付けず、公開前特例の履歴検査は発注IDを求める。既存の補完コマンドを起動時の理由から案内する。
- 前身継承は現行の特例で明示的に対象外。継承分を含む巡数のまま、対象外の理由と人間承認の取り方を表示する。
- 課題番号なしの4件目は独立した上限で停止する。exit 4 の表示に、課題の起票・継承行の記入・対象の切替を追記する。

## 3経路の原因と観測範囲

起動口は `bin/codex-review:29–41` で種別を検査し、`bin/codex-review:101–113` で巡数ゲートのJSONと終了コードを受け取る。 `REVIEW_PRERELEASE_RECORD` は `lib/round_gate.py:1166` で本文の裁定を指すIDとして受け取る。通常判定を先に実行し、通常判定が不通過で、かつIDを指定したときに特例を評価する（`lib/round_gate.py:1360–1376`）。要約にある番号と起動名を整える `bin/_codex_common.sh:59–103` は別の処理。巡を数える対象は `REVIEW_TARGET` で決まる。

## 最小の設計

1. **書式の不一致。** `lib/prerelease.py` のIDなし数値行と、壊れた表・不正IDを理由の文言で区別する。既存と同じ不通過分岐から、既存の7列・種別・HEADの書式に合うIDなしの表行には「公開前特例不成立 — 巡の履歴に発注IDがありません。codex-history-backfill で補完案を確認してください」と1行で案内する。旧計数のID要求にも同じ案内を付ける。書式の区別は診断の選択だけに使い、どちらの履歴読取りでも受理条件を増減させない。既存コマンドは同じ対象・巡・種別・日時・短縮HEAD・レビュアーが一対一で一致する場合だけ候補を出す（`lib/history_backfill.py:22–59`）。候補は担当が正本と照合して反映する。補完後も改めて厳格評価する。曖昧な候補、欠損、矛盾はそのまま拒否し、HEADだけから発注IDを推定しない。規則blobの不一致が先なら現行の規則エラーを表示する。
2. **前身継承。** `lib/prerelease.py:198–199,241–242` の複合メッセージを、blocking・前身・種別不一致の実際の理由に分ける。前身の文言は「公開前特例不成立 — 前身の巡を継承する系列は対象外です。継承込みの今回巡の人間承認／必要な裁定を本文に記録してください」。既存の `decision.message` に出す。照合不一致（247行）は「正本履歴と判定巡が一致しません」を使い、前身指定も確認先に挙げる。起動時の指定だけを根拠に新たな拒否条件を足す必要はない。継承を特例でも許可するには、各前身の正本履歴・系列境界・固定上限を再確認と予約まで束縛する設計が要る。今回は診断で要件を満たす。
3. **起動口での表示。** 通常判定で止まった巡3〜5で裁定IDの指定がない場合は、既存の拒否メッセージに「特例を使う場合は本文の公開前裁定と REVIEW_PRERELEASE_RECORD を確認」を付ける。この表示だけでは登録済みPJや適用可否は確定しない。特例を明示指定したのに通常ルートが先に通過した場合は、既存JSONの `message` に通常判定を優先した旨を付け、起動口でstderrへ1行出す。特例の評価は起動しない。理由が付く範囲はこの二つと評価器が呼ばれて返した拒否。手前の入力検証・巡数計算失敗・送信前再照合は各自のエラーを表示する。起動名を返すstdout、診断モードのJSON、既存の終了コードと `authority` は保つ。新しい案内は固定文言を使い、本文や裁定の生データを表示しない。
4. **番号なしの上限。** `lib/round_gate.py:1286` の停止メッセージだけに手順を足す。「課題を起票し、本文に先行発注の継承行（run ID・種別・消化した回数）を書いてから、REVIEW_TARGET を issue:owner/repo#N に設定して再判定してください」。実在する前身PRを継承する場合は既存の `前身 PR #N で 設計K巡・コードM巡 消化済み（継承）。` を使い、番号なし分は監査できるよう本文に記録する。番号なし分の記述は人間が継続判断に使う記録で、ゲートが自動加算する継承行の構文にはしない。既存の人間承認と累計管理は続ける。起票、本文編集、台帳変更、再発注は案内の利用者が判断する。
